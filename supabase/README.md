# Supabase: مرجع الشيفرة المنشورة

المشروع المرتبط: `webqpbcijjbawatykoxe`. جُمعت المصادر من المشروع الفعلي في ٢ نوفمبر ٢٠٢٦ باستخدام قراءات فقط. يحتوي `deployment-inventory.json` على إصدارات الوظائف والترحيلات والجداول ومواعيد المهام؛ لا يحتوي بيانات المشاركين أو قيم الأسرار أو أوامر cron التي قد تضم اعتمادًا.

## الوظائف

| الوظيفة | المسؤولية |
| --- | --- |
| `telegram-webhook` | التفعيل واستقبال رسائل وأزرار البوت |
| `send-reminders` | التذكير الدوري بالأجزاء غير المكتملة |
| `notify-done` | رسالة إتمام الجزء |
| `send-completions` | عامل طابور إشعارات اكتمال الختمة |
| `announce` | إعلان اكتمال الختمة أو بدء دورة جديدة |
| `send-message` | رسائل المنظم |
| `cancel-khatmah` | إنهاء الختمة وفق صلاحية المنظم |
| `migration-handoff` | نقطة نقل متقاعدة تعيد 410 |
| `telegram-migration` | نقطة نقل تلغرام متقاعدة تعيد 410 |

القيم `verify_jwt` في المخزون تصف المنشور بالفعل؛ لا تعني أن جميع النقاط عامة بلا تحقق. الوظائف تستخدم تحقق سر webhook أو cron أو صلاحيات RPC بحسب الدور. لم تُنشر وظائف جديدة خلال التنظيف؛ الملفات المسترجعة تطابق المصادر المنشورة.

أسماء متغيرات البيئة المستخدمة: `TELEGRAM_BOT_TOKEN` و`TELEGRAM_WEBHOOK_SECRET` و`SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` و`CRON_SECRET` و`APP_TIME_ZONE` و`APP_URL`. تُدار قيمها في أسرار Supabase؛ لا تُنسخ إلى ملفات الواجهة.

## الترحيلات وحدود إعادة الإنشاء

`migrations/` نسخ من **سجل الترحيلات الموجود فعلًا** بأرقامه الأصلية، وليس سلسلة ترحيلات جديدة. يتضمن إصلاح الإكمال الفوري `20261101062026_instant_durable_khatmah_completion_notifications.sql` المنشور في ١ نوفمبر. لا تعِد تطبيقه على الإنتاج.

المجلد `schema/` يحتفظ بثلاثة سكربتات SQL تاريخية يدوية من المستودع السابق، للتتبع والمقارنة فقط. ليست أمر إعداد شاملًا، وبعضها يكرر تغييرات محفوظة في migrations. لا تشغّل المجلدين معًا كخطوة تثبيت.

**سجل الترحيلات يبدأ بعد إنشاء القاعدة الأولى. لذلك لا يكفي وحده لإعادة بناء قاعدة فارغة.** يلزم تصدير schema-only كامل ومراجع وإنشاء مسار استعادة في قاعدة اختبار منفصلة قبل اعتبار الاستعادة موثقة نهائيًا. لا توجد في هذا التنظيف قاعدة تطوير جديدة أو تغييرات إنتاج أو ترحيلات مطبقة.

## مهام الخلفية والتحقق الأمني

تُظهر القراءة الفعلية مهام فعالة للتذكير كل خمس دقائق، وإعادة محاولة إشعارات الإكمال كل دقيقة، والتنظيف الأسبوعي. الإكمال الفوري نفسه يعتمد trigger وطابورًا؛ المهمة الدورية وسيلة إعادة محاولة.

كل الجداول الأربعة عشر المرصودة في `public` و`private` لديها RLS مفعّل دون سياسات صفوف. التطبيق يعتمد وظائف RPC المصرّح بها بدل القراءة المباشرة للجداول. أعاد Advisor أيضًا تحذيرات عن ٢٥ وظيفة SECURITY DEFINER قابلة لاستدعاء anon و٦ قابلة لاستدعاء authenticated. هذه تنبيهات تحتاج مراجعة التحقق داخل كل وظيفة، وليست إثباتًا منفردًا لوجود ثغرة. لم تُلغَ صلاحيات RPC جماعيًا لأن ذلك يوقف وظائف التطبيق.

راجع [تنبيه RLS دون سياسات](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) و[تنبيه وظائف anon](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable) و[تنبيه وظائف authenticated](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable). المراجعة الحالية ليست تدقيق اختراق أو مراجعة صلاحيات كاملة.
