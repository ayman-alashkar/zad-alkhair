# بنية المشروع

## الواجهة

واجهة ثابتة دون إطار عمل أو حزم npm. `src/home/` يضم هوية الجهاز والمشاركة في الختمات وإدارتها والتذكيرات وواجهة الصلاة والتثبيت. `src/reader/` يضم عرض المصحف والتفسير ومصادر الصوت والتوقيت وقوائم التشغيل والتكرار والمؤقت والتنزيل.

يُنتج `scripts/build-app.cjs` الصفحة الرئيسية ومدخل القارئ `/quran-read/` مع CSS وJavaScript مضمنين لفتحهما من النسخ المحفوظة دون اتصال. تستخدم روابط السور والتلاوة قالب القارئ نفسه، وتحمّل ملفي CSS وJavaScript المشتركين من `quran/runtime/`. يُشتق رقم إصدار الملفين من محتواهما.

التقسيم الحالي يفصل HTML وCSS ويقسم JavaScript حسب المسؤولية. app.js يحدد ترتيب الأقسام بعلامات @include؛ يوسّعها scripts/app-source.cjs عند البناء مع رفض التكرار والأقسام غير المربوطة. بقي الناتج مطابقًا بايتًا ببايت بعد تقسيم الأقسام.

- home: محتوى، خريطة السور (`quran-map.js`)، تثبيت وروابط، صلاة، API، تنسيق وساعة، مطابقة أسماء، جلسة، طابور إشعارات، حساب، عرض، حوارات، تحديث حالة، Telegram، منظّم، أفعال، ربط الواجهة، الشاشة الرئيسية «اليوم» (`today.js`)، شاشة مواقيت الصلاة والتقويم الهجري (`prayer-screen.js`)، وإقلاع.
- reader: تفسير، قراء، حالة، عرض مصحف، ملاءمة صفحة، أدوات قراءة، مكتبة، مصادر صوت، واجهة مشغّل، تشغيل صوت، تحكم ونقل، قائمة، واجهة قائمة، مظهر، عمل دون اتصال، وإقلاع.

هذه أقسام مصدر تتشارك النطاق الأصلي، وليست ES modules معزولة. عزل الحالة والاعتمادات بواجهات مستقلة يبقى خطوة لاحقة تحتاج اختبارات تكامل للمستخدم. اختبارات ملاءمة الصفحة والقراء والنقل الصوتي الآن تقرأ أقسام المصدر الفعلية كاملة؛ لا تستخرج شيفرةً بحدود نصية من HTML.

يربط `src/home/state-sync.js` كل طلب تحديث برمز الختمة ورقم الطلب. تُهمل الاستجابة إذا غادر المستخدم الختمة أو إذا سبقها طلب أحدث.

### الشريط السفلي وطبقات العرض

الشريط السفلي `#zk-tabs` ثابت فوق الرئيسية وشاشات الختمة، وطبقته 130. كل ما يُفتح فوقه يجب أن يكون أعلى منه، وإلا اختفى تحته:

| العنصر | الطبقة |
| --- | --- |
| شاشة «اليوم» (`.zk-launch`) | 120 |
| الشريط السفلي (`.zk-tabs`) | 130 |
| خلفية اللوحة ولوحة الجزء (`.scrim` و`.sheet`) | 135 و136 |
| النوافذ (`.modal`) | 140 |
| نافذة التأكيد (`.app-confirm-overlay`) | 145 |
| نافذة الصلاة فوق «اليوم» | 150 |
| التنبيه القصير (`.toast`) | 160 |

`tests/layers.test.cjs` يمنع عودة هذا الترتيب إلى الخطأ. للقارئ ترتيبه الخاص: خلفية اللوحات 145، والتنبيه 155.

## صفحات الاكتشاف

`src/discovery/catalog.json` هو مصدر أسماء السور وعدد آياتها ووصف الأجزاء وقائمة القراء المنشورين في الفهرس. المولّد لا يستخرج هذه البيانات من ناتجه بعد الآن. قائمة المشغّل تحتوي أيضًا مصدرًا صوتيًا إضافيًا لا توجد له صفحة اكتشاف مستقلة؛ لا يُفترض تساوي عدد القائمتين تلقائيًا.

يولّد `build-seo-pages.cjs` الفهرس العام `/quran-index/` وصفحات الأجزاء والقرّاء، ويحدّث «عن التطبيق» و«الختمات» وخريطة الموقع. على النطاق الرسمي، تتضمن الخريطة صفحات القراءة المباشرة للسور الـ١١٤. تستخدم صفحات الاستماع وسم `noindex` وتتاح للمشاركة. تفتح أزرار قراءة الأجزاء المصحف عبر `/quran-read/?juz=8`، ويستخدم استئناف صفحة محددة المعامل `page`. يعرض `npm run check:generated` الأعداد الحالية ويتحقق من تطابق ملفات النشر مع مصادرها.

## البيانات والتبعيات

- نصوص التفسير محلية، بسجل SHA-256 لكل نص وبصمات ملفات في manifest. يعالج التحقق ٦٢٣٦ سجل آية و٦٠ سجل فضيلة.
- بيانات المصحف وخطوطه من `quran-qcf4@1.0.3` المثبّتة بالإصدار. عنوان السورة الزخرفي من Tarteel وله بديل في القارئ.
- مصادر الصوت وتوقيتها تختلف حسب القارئ: EveryAyah وMP3Quran ومصدر السور الكاملة. لا يجوز تبديل تسجيل القارئ دون مطابقة توقيت الآيات. مصدر توقيت ماهر مثبت بتعهد Git ومسجل في `data/maher-timing-source.json`.
- الخطوط العربية المحلية والأيقونات في `fonts/` و`icons/`. حاسبة الصلاة المحلية في `vendor/`.
- الاتصالات الخلفية عبر RPC وEdge Functions. مفتاح الواجهة `sb_publishable_…` عام بطبيعته؛ مفاتيح الخادم ورمز البوت لا توضع في الواجهة أو المستودع.

## العمل دون اتصال

| المخزن | الاستخدام |
| --- | --- |
| `zad-shell-stable-v1` | وثيقتا التطبيق والملفات المشتركة |
| `zad-shell-backup-v1` | آخر وثيقتين سليمتين قبل التحديث |
| `zad-shell-stage-*` | تجهيز تحديث الوثيقتين قبل استبدالهما |
| `zad-quran-core-v1` | بيانات المصحف وخطوطه |
| `zad-tafsir-alwajeez-v1` | التفسير المحلي |
| `zad-audio-v1` | التلاوات التي اختار المستخدم تنزيلها |
| `zad-runtime-*` | موارد تشغيل أخرى |

الحفاظ على أسماء مخازن المصحف والتفسير والصوت جزء من التوافق مع التطبيقات المثبتة. عند ترقية نسخة مثبّتة، يمكن نسخ وثيقة القارئ المحفوظة إلى مفتاح `/quran-read/` حتى يكتمل تحديثها من الشبكة. يُختبر فشل الشبكة والتحديث المبتور والتنقل عبر مسارات القراءة والاستماع وطلبات الصوت الجزئية. إصلاح البقرة يستبدل النسخة غير الصالحة وحدها، ويترك بقية التنزيلات.

## رؤوس الاستضافة

`_headers` يضبط رؤوس الأمان لكل الصفحات:

- منع التضمين في إطار (`X-Frame-Options` و`frame-ancestors`).
- `nosniff`.
- سياسة الإحالة.
- HSTS لسنة.
- `Permissions-Policy`: تعطّل ما لا يستعمله التطبيق، وتسمح بالمشاركة والنسخ.

لم تُضف سياسة CSP كاملة، لأن الشيفرة مدمجة داخل الصفحات وتطلب موارد من عدة نطاقات (المصحف والصوت وSupabase). إضافتها تحتاج حصرًا دقيقًا لهذه النطاقات واختبارًا في المتصفح.

الفيديو في `/Zad-Alkhair-Player-Guide.mp4` أونلاين فقط. الصفحة لا تربط مصدر الفيديو قبل ضغط التشغيل، وطلبات الفيديو تتجاوز Cache Storage باستخدام `no-store`. بطاقة الدليل المعتمدة `social/player-guide-card-v6.jpg`؛ الملفات القديمة المحذوفة لها تحويلات إلى هذه البطاقة.

## التوافق مع الروابط القديمة

`migration.js` يحوّل نطاق GitHub Pages إلى النطاق الحالي ويحافظ على المسار والمعاملات والجزء بعد `#`، ويطلب التخزين الدائم على النطاق الحالي. صفحات `transfer/` و`cleanup/` و`telegram-transfer/` تحويلات متقاعدة؛ وجودها يحمي الروابط المحفوظة. وظائف النقل المتقاعدة تعيد 410، ولا تُفعّل من جديد ضمن تنظيف الملفات.
